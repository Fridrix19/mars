Принципы

Пять правил, по которым принимаются решения, когда в документе нет готового ответа. Если новый компонент нарушает одно из них — сначала меняется правило, потом компонент.

Одно действие на экран

В видимой области ровно одна залитая кнопка. Всё остальное — ghost, ссылки и плитки. Пользователь всегда видит, что делать дальше.

Цифры — моноширинные

Суммы, курс, номиналы и номера — JetBrains Mono с табличными цифрами. Итог не «прыгает» при пересчёте, столбцы выравниваются сами.

Роли, не значения

Компоненты знают только роли (--accent, --surface), а не примитивы. Тема меняется подменой ролей; ни одна кнопка не правится вручную.

Логотипы не трогаем

Иконки категорий и логотипы сервисов используются как есть: не перекрашиваются, не обрезаются, не заменяются. Меняется только подложка под ними.

Движение — opt-in

Анимации живут внутри prefers-reduced-motion: no-preference. Без них страница полностью рабочая, у каждого состояния есть цвет или текст.

Ошибка — инструкция

Сообщение говорит, что случилось и как исправить, рядом с местом поломки. Без «Упс», без восклицательных знаков, без «мы столкнулись с проблемой».

Как пользоваться документом

Каждый компонент описан по одной схеме: живое превью, таблица размеров и токенов, состояния, «можно / нельзя» и соответствие в PrimeVue. У превью есть кнопка «Код» — она показывает разметку, которую можно копировать. Переключатель «Превью компонентов» в шапке показывает те же компоненты в тёмной теме сайта; у каждого превью есть и локальный переключатель.

Источник правды — токены. Все значения в таблицах взяты из base.css и pv-preset.js. Если документ и код разошлись — прав код, документ обновляется в тот же день.
